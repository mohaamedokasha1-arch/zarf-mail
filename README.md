## 🔥 ما الجديد في الإصدار 2.0؟

**خدمة mail.tm أصبحت هي الأساس الذي يُبنى عليه كل شيء في ظرف**:

| | |
|---|---|
| 🌍 **دومينات حقيقية** | كل بريد ينشئه ظرف هو **حساب بريد فعلي** يستقبل من أي مكان في الإنترنت (Google، Instagram، أي موقع) — بدون إعداد MX ولا سيرفر SMTP |
| ⚡ **وصول خلال ثوانٍ** | عامل مزامنة ذكي يجلب الرسائل الجديدة ويستخرج كود التحقق تلقائياً |
| 🧠 **استقصاء تكيّفي** | كلما زاد عدد المستخدمين، تباعدت المزامنة تلقائياً — **لا نتجاوز حصة 30 طلب/دقيقة أبداً** |
| 🔑 **استخراج OTP** | الكود يُستخرج فور وصول الرسالة ويظهر باللون البارز أعلى الصفحة وفي المودال |
| ⏳ **حذف تلقائي بعد 7 أيام** | كل بريد ورسالة صالحة **7 أيام كاملة**، ثم نحذفها **من ظرف ومن mail.tm معاً** — والواجهة تعرض عدّاداً تنازلياً بالأيام |
| 🌐 **12 لغة بتبديل فوري** | قائمة لغات أنيقة في الهيدر تبدّل كل نصوص الواجهة بلا إعادة تحميل، وتقلب الاتجاه `rtl/ltr` تلقائياً |
| 🧩 **مزوّدات قابلة للتبديل** | `mailtm` (الأساسي) · `local` (SMTP/Webhook) · `hybrid` (الاثنان) |

## 📐 المعمارية: كيف يتصل ظرف بـ mail.tm؟

```
المستخدم يفتح ظرف
      │
      ▼
POST /api/generate-email
      │
      ├─1─▶ GET  https://api.mail.tm/domains          (الدومين الحقيقي، مُخزّن 15 دقيقة)
      ├─2─▶ POST https://api.mail.tm/accounts         { address, password }
      └─3─▶ POST https://api.mail.tm/token            { address, password } ← التوكن
                                                        │
      ◀───────── يُحفظ في SQLite (address + password + JWT) ─────────┘

المستخدم ينسخ العنوان ويسجّل به في أي موقع
      │
      ▼
مرسل خارجي ──▶ سيرفر MX الخاص بـ mail.tm ──▶ صندوقك على الخدمة
                                                    │
      ┌─────────────────────────────────────────────┘
      ▼  (كل 10 ثوانٍ، بحد أقصى 18 طلب/دقيقة، للصناديق النشطة فقط)
GET https://api.mail.tm/messages      ← قائمة الرسائل   (طلب واحد)
GET https://api.mail.tm/messages/{id} ← المحتوى الكامل  (للرسائل الجديدة فقط)
      │
      ▼
تنظيف HTML ◀ استخراج OTP ◀ حفظ في SQLite ◀ بثّ SSE للمتصفح
      │
      ▼
الواجهة تقرأ من **SQLite المحلية** (سريع، بلا استهلاك للحصة)
      │
      ▼  (بعد ساعة)
DELETE /messages/{id}  +  DELETE /accounts/{id}   ← حذف من الخدمة البعيدة
```

## 🧪 أسرار الخدمة التي اكتشفناها بالاختبار الحقيقي (مُطبّقة في الكود)

خلال بناء التكامل، اختبرنا الـ API مباشرةً وظهرت سلوكيات غير موثّقة في الصفحة الرسمية.
**ظرف يتعامل مع كل واحدة منها تلقائياً**:

| # | الاكتشاف | كيف يعالجه ظرف |
|---|---|---|
| 1 | ⚠️ **النقطة (.) في اسم المستخدم تُفشل `/token` دائماً** (`401 Invalid credentials`) مع أن `/accounts` يقبلها | المولّد يستخدم `_` و`-` فقط، وأي اسم مخصص تُحوَّل نقطته تلقائياً إلى `_` |
| 2 | ⏱ **تأخير تنشيط ~3 ثوانٍ** بين إنشاء الحساب وصلاحية التوكن | إعادة محاولة `/token` بفواصل متزايدة: 3.5s → 4s → 5s → 7s → 9s |
| 3 | 🚦 **الحدّ 30 طلب/دقيقة لكل IP** (`429` + ترويسة `Retry-After`) | Token Bucket عام + مزامنة تكيّفية + تبريد تلقائي عند 429 |
| 4 | 📦 **حقل `html` يأتي كمصفوفة نصوص** وليس نصاً واحداً | دمج المصفوفة قبل التنظيف والعرض |
| 5 | 📡 **لا يوجد Webhook/SSE للسيرفرات** (مسار Mercure غير مكشوف: `.well-known/mercure` → 404) | عامل مزامنة داخلي + بثّ SSE خاص بظرف للمتصفح |
| 6 | 🔁 **الاسم المكرر لدى الخدمة يرجع 422** (وليس 409) | نفرّق: 422 = نجرّب اسماً آخر، 409 = تكرار محلي نُبلغ به المستخدم |
| 7 | 🔑 **التوكن JWT بلا `exp`** | تحديث استباقي عند أي 401، وحفظ التوكن الجديد في قاعدة البيانات |

## 🚀 التشغيل في دقيقة

```bash
cd zarf-mail
npm install
npm run build:css     # ملف CSS مبني مسبقاً أيضاً
npm start             # → http://localhost:3000
```

لا تحتاج أي شيء آخر: لا دومين، لا MX، لا سيرفر SMTP.
افتح الصفحة → يظهر بريد حقيقي فوراً → اضغط **«أرسل رسالة تجريبية»** لتصل رسالة فعلية خلال ثوانٍ.

> زر «أرسل رسالة تجريبية» مع mail.tm يرسل **بريداً حقيقياً** عبر SMTP مباشر إلى سيرفر
> الدومين (`in.mail.tm`) — فإن كان البورت 25 مغلقاً عندك سترى رسالة خطأ واضحة،
> ويمكنك حينها تجربة إرسال رسالة من بريدك الشخصي إلى العنوان الظاهر في الصفحة.

## ⚙️ متغيرات البيئة الخاصة بالمزوّد

| المتغير | الافتراضي | الشرح |
|---|---|---|
| `MAIL_PROVIDER` | `mailtm` | `mailtm` · `local` · `hybrid` |
| `MAILTM_API_BASE` | `https://api.mail.tm` | رأس الـ API |
| `MAILTM_POLL_INTERVAL_MS` | `10000` | **الفاصل الأساسي** للمزامنة (يتزايد تلقائياً مع عدد المستخدمين) |
| `MAILTM_RATE_LIMIT_PER_MIN` | `18` | ميزانية الطلبات في الدقيقة (الحد الرسمي 30 — نترك هامش أمان) |
| `MAILTM_MAX_MAILBOXES_PER_CYCLE` | `8` | أقصى صناديق تُزامن في الدورة |
| `MAILTM_ACTIVE_WINDOW_MIN` | `15` | الصناديق غير المفتوحة خلال هذه المدة **لا تُزامن** (توفير الحصة) |
| `MAILTM_TOKEN_ATTEMPTS` | `5` | محاولات الحصول على التوكن بعد إنشاء الحساب |
| `MAILTM_DOMAINS_CACHE_MINUTES` | `15` | مدة تخزين قائمة الدومينات |
| `MAILTM_MARK_SEEN` | `false` | تعليم الرسالة مقروءة على الخدمة (طلب إضافي لكل رسالة) |
| `MAILTM_DELETE_ON_EXPIRE` | `true` | حذف الرسالة والحساب من mail.tm بعد انتهاء الساعة |
| `MAILTM_MANUAL_SYNC_THROTTLE_MS` | `3000` | أقل فاصل بين مزامنة يدوية (ضغطة «تحديث») |

بقية المتغيرات (مدة الحياة، الحدود،_rate limit_ العام، SMTP المحلي، الويب هوك) في ملف `.env.example`.

## 🔌 توثيق الـ API (واجهة ظرف)

الأساس: `https://your-domain/api`

| الطريقة | المسار | الوصف |
|---|---|---|
| `GET` | `/health` | الحالة + ميزانية الطلبات المتبقية |
| `GET` | `/provider` | ⭐ معلومات المزوّد (mail.tm) وإحصائيات العميل |
| `GET` | `/domains` | الدومينات الحقيقية المتاحة الآن |
| `POST` | `/generate-email` | إنشاء بريد (عشوائي أو `{"custom":"ahmed"}`) |
| `GET` | `/check-inbox/:emailId` | الصندوق · `?sync=1` لمزامنة فورية من mail.tm |
| `GET` | `/inbox/:emailId/otp` | آخر كود تحقق |
| `GET` | `/messages/:emailId/:id` | تفاصيل رسالة كاملة |
| `POST` | `/messages/:emailId/:id/read` | تعليم كمقروءة |
| `DELETE` | `/messages/:emailId/:id` | حذف رسالة (محلياً + من الخدمة) |
| `POST`/`DELETE` | `/delete-email` | حذف البريد والحساب (يحتاج التوكن) |
| `GET` | `/stream/:emailId` | بثّ SSE لوصول رسائل جديدة |
| `POST` | `/demo/inject` | إرسال رسالة تجريبية (حقيقية مع mail.tm) |
| `POST` | `/inbound/webhook` | استقبال RAW/Form — **للوضع المحلي فقط** |

### أمثلة سريعة

```bash
# 1) المزوّد وميزانية الطلبات
curl http://localhost:3000/api/provider

# 2) الدومينات الحقيقية الآن
curl http://localhost:3000/api/domains
# → {"success":true,"provider":"mailtm","real":true,"domains":["emalupe.com"],…}

# 3) إنشاء بريد (ينشئ حساباً حقيقياً + توكن خلال ~4 ثوانٍ)
curl -X POST http://localhost:3000/api/generate-email -H "Content-Type: application/json" -d '{}'
# → {"data":{"address":"nova_falcon_a91f2b@emalupe.com","realInbox":true,"token":"eyJ…"}}

# 4) بريد باسم مخصص (النقطة تتحول تلقائياً إلى _)
curl -X POST http://localhost:3000/api/generate-email -H "Content-Type: application/json" \
  -d '{"custom":"ahmed.mohsen"}'      # → ahmed_mohsen@emalupe.com

# 5) فحص الصندوق مع مزامنة فورية
curl "http://localhost:3000/api/check-inbox/EMAIL_ID?sync=1"
```

## 🧩 الأوضاع الثلاثة

### 1) `MAIL_PROVIDER=mailtm` (الأساسي — الافتراضي)
دومينات حقيقية، لا يحتاج أي إعداد DNS. **موصى به للإطلاق الفوري.**

### 2) `MAIL_PROVIDER=local`
استقبال عبر سيرفر SMTP المدمج أو ويب هوك Cloudflare/Mailgun — مناسب إن كان لديك دومين خاص وتريد تحكماً كاملاً:
```bash
MAIL_PROVIDER=local SMTP_PORT=25 MAIL_DOMAINS=zarf.yourdomain.com sudo npm start
```

### 3) `MAIL_PROVIDER=hybrid`
الاثنان معاً: البريد الحقيقي من mail.tm + استقبال محلي عبر SMTP/ويب هوك.

## ⏳ مهلة الـ 7 أيام (صيانة الخصوصية)

| | |
|---|---|
| **المدة** | **7 أيام كاملة** (10,080 دقيقة) للبريد ولكل رسالة |
| **المنفّذ** | عامل تنظيف داخلي كل `CLEANUP_INTERVAL_MINUTES` (ساعة) + سكربت كرون مستقل `scripts/cleanup.js` |
| **المحذوف** | الرسالة والصندوق **محلياً من SQLite**، والنسخة الأصلية **بعيداً على mail.tm** (`DELETE /messages/{id}` ثم `DELETE /accounts/{id}`) |
| **قبل الحذف** | لا شيء — الحذف يحدث **فقط** عند تجاوز `expires_at` |
| **ما تراه الواجهة** | `ttlDays: 7` · `remaining: {days, hours, minutes, seconds}` · `remainingLabel: "6 يوم و 23:59"` · عدّاد `6d 23:59:58` وملاحظة «صالح لمدة 7 أيام» |

```bash
# التحقق
curl -s http://127.0.0.1:3000/api/health | jq '{ttlDays, ttlMinutes}'
# → { "ttlDays": { "mailbox": 7, "message": 7 }, "ttlMinutes": { "mailbox": 10080, "message": 10080 } }

# سطر الكرون (كل ساعة)
0 * * * * cd /path/to/zarf-mail && /usr/bin/node scripts/cleanup.js >> /var/log/zarf-cleanup.log 2>&1
```

> خدمة mail.tm نفسها تضع `"retention": true` و`"retentionDate"` بعد 7 أيام من الإنشاء —
> أي أن الوعد مطابق للواقع على الجانبين.

📄 الكود الخلفي كاملاً: [`docs/RETENTION-7-DAYS.md`](docs/RETENTION-7-DAYS.md)

## 🌍 النشر

يعمل ظرف على أي منصة Node.js — **لا يحتاج بورت 25 ولا سجلات MX** لأن mail.tm يستقبل البريد نيابةً عنا:

| المنصة | ملاحظة |
|---|---|
| **Render** | Build: `npm install && npm run build:css` · Start: `npm start` |
| **Railway / Koyeb** | `railway up` ثم أضف المتغيرات |
| **VPS** | `pm2 start server/index.js` + Nginx (راجع إعداد `proxy_buffering off` لـ SSE) |
| **Docker** | `docker build -t zarf-mail . && docker run -p 3000:3000 -v zarf-data:/app/data zarf-mail` |

> ⚠️ الحصة (30 طلب/دقيقة) تُحسب **لكل IP**، أي أن كل مستخدمي نسختك يتشاركون نفس الحصة.
> نظام المزامنة التكيّفي في ظرف يتعامل مع هذا تلقائياً: كلما زاد المستخدمون تباعدت
> مزامنة كل صندوق (وضغطة «تحديث» تبقى فورية دائماً عبر `?sync=1`).

## 🔒 الأمان والخصوصية

- **تنظيف HTML** من السكربتات والأحداث والتتبع قبل التخزين.
- **عرض معزول**: محتوى HTML داخل `<iframe sandbox="">`.
- **CSP + Helmet** + CORS + تقييد معدّل + توكن للحذف.
- **حذف مزدوج**: بعد ساعة تُمحى الرسالة والحساب من قاعدة ظرف **ومن خدمة mail.tm**.
- **لا نخزّن بيانات شخصية**: لا تسجيل، لا كلمات مرور حقيقية (كلمة مرور الحساب المؤقت عشوائية ولا تُعرض للمستخدم).
